# Network Expansion

<Callout type="warn">
The retired v1 architecture actively scanned a contact's connections list via Playwright to discover 2nd-degree contacts (`deep-scan.mjs`, `batch-deep-scan.mjs`). That capability has no v2 equivalent -- the agent cannot drive a browser at all. Network growth in v2 is **passive**: it happens as you browse LinkedIn with the extension installed, not as an automated batch job the agent runs on your behalf.
</Callout>

## How Your Network Grows in v2

### Passive capture while browsing

The browser extension captures profile and search-result data from any LinkedIn page you visit while it's active. There is no equivalent to "scan this contact's connections" -- you grow your captured network by visiting pages yourself (profiles, search results, company pages).

### Auto-paginate search results

When you capture a LinkedIn people-search or content-search results page, the extension can automatically continue to the next page of results and capture that too. This is opt-in via a popup setting (`autoPaginate`).

**How it works:**

1. You capture a `SEARCH_PEOPLE` or `SEARCH_CONTENT` results page (manually, or the extension does it as you browse).
2. The server (`POST /api/extension/capture`) creates a follow-up task for the next page of results, up to a configured cap (`MAX_SEARCH_PAGES`).
3. If `autoPaginate` is enabled, the extension's service worker waits ~2 seconds, navigates the active tab to that next-page URL, and re-fires capture once the page finishes loading.
4. This repeats until the server stops creating follow-up tasks at the `MAX_SEARCH_PAGES` cap.

This is the closest v2 equivalent to "batch discovery" -- it expands coverage of a single search's results automatically, rather than fanning out through a target contact's connections.

### Importing existing data

For a one-time bulk expansion, import a LinkedIn data export:

```
POST /api/import/from-directory
{ "path": "/path/to/linkedin/export" }
```

or a CSV:

```
POST /api/import/csv
```

## Growing Toward Your ICP

Since there's no automated deep-scan to prioritize, the practical strategy is:

1. **Define niches** with search keywords that match your ICP (see [ICP Configuration](/docs/claude-agent/icp-configuration)).
2. **Search LinkedIn manually** using those keywords, with the extension active and `autoPaginate` on to sweep each results page.
3. **Rescore regularly** as new contacts come in: `/network-intel rescore everything`.
4. **Use `recommend`** to see what the app suggests doing next with your current data:

```
/network-intel what should I focus on next?
```

## Graph Analysis of What You Have

Even without active deep-scanning, the app computes graph metrics and community clusters over whatever contacts and edges you've captured:

```
POST /api/graph/compute   # recompute metrics + detect communities
GET  /api/graph/data      # nodes/edges for visualization
GET  /api/graph/communities  # cluster listing
```

```
/network-intel recompute the graph
/network-intel show me clusters
```

Bridge/connector contacts (people who span multiple clusters) still show up in this analysis -- they're just derived from whatever data you've captured, not discovered by an automated scanning pass.

## What Changed From v1

| Capability | v1 | v2 |
|-------------|----|----|
| Discover a contact's connections | `deep-scan.mjs --url <profile>` (Playwright) | Not available |
| Batch-prioritized expansion | `batch-deep-scan.mjs --criteria gold\|referral\|hub\|all` | Not available |
| Bridge contact detection across scans | Tracked via `discoveredVia` in `contacts.json` | Not tracked as a distinct concept; graph community detection is the closest analog |
| Expand a single search's results | Manual re-search | Automated via extension `autoPaginate` |
| Rate-limit protection for automation | Configurable delay/page-limit flags | N/A -- there is no automated browsing to rate-limit; capture follows your own browsing pace |
| Snapshot / delta tracking of network changes | `delta.mjs --snapshot / --check / --list` | Not available -- see [Analysis Modes](/docs/claude-agent/analysis-modes#modes-with-no-v2-equivalent) for other retired capabilities |

If you need automated multi-hop network discovery, it would have to be rebuilt -- there is currently no server-side or agent-side equivalent to the v1 deep-scan pipeline.
