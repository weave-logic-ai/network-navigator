# Analysis Modes

`analyze.mjs` supports eight read-only analysis modes, each mapping to a single `GET` request against the app's API. All of them operate on live data in PostgreSQL -- there is no local `graph.json` or cached snapshot.

<Callout type="warn">
The retired v1 analyzer supported twelve modes, including `behavioral`, `visibility`, `employers`, and `similar`. Those four have no v2 equivalent in `analyze.mjs` -- see the note at the bottom of this page.
</Callout>

## 1. summary

High-level overview of your entire network.

**Calls:** `GET /api/dashboard`

**Returns:** Whatever the dashboard endpoint exposes at the top level -- contact counts, tier breakdown, enrichment status, budget usage, and recent activity. The script prints every key in the response, so its output tracks the dashboard endpoint's shape directly.

```
/network-intel give me an overview
```

```bash
node scripts/analyze.mjs --mode summary
```

## 2. hubs

Identifies your most connected and influential contacts.

**Calls:** `GET /api/graph/data`

**Returns:** Graph nodes with a score, sorted descending, printed as name/company/score/connections.

```
/network-intel who are my best hubs?
```

```bash
node scripts/analyze.mjs --mode hubs --top 15
```

## 3. prospects

Identifies best potential buyers based on composite score.

**Calls:** `GET /api/contacts?sort=compositeScore&order=desc&limit=<top>`

**Returns:** Contacts ranked by composite score, printed as name/company/title/score/tier.

```
/network-intel find my top prospects
```

```bash
node scripts/analyze.mjs --mode prospects --top 20
```

## 4. referrals

Identifies your best referral partners -- people who can send you business.

**Calls:** `GET /api/contacts?sort=referralLikelihood&order=desc&limit=<top>`, falling back to fetching the top 100 by composite score and filtering/sorting client-side by `referralLikelihood`/`referralScore` if the primary sort isn't supported.

**Returns:** Contacts with referral score and persona, printed as name/company/title/referral-score/persona.

```
/network-intel who are my best referral partners?
```

```bash
node scripts/analyze.mjs --mode referrals --top 20
```

## 5. clusters

Maps your network by graph community.

**Calls:** `GET /api/graph/communities`

**Returns:** Each cluster with a name/label and up to 5 sample members (plus a count of any remaining).

```
/network-intel show me clusters
```

```bash
node scripts/analyze.mjs --mode clusters
```

If this returns nothing, run `pipeline.mjs --compute-graph` first -- clusters are computed, not stored automatically as contacts are added.

## 6. search

Combined keyword and vector search across contacts.

**Calls:** `GET /api/contacts/hybrid-search?q=<query>`

**Returns:** Up to 20 matching contacts, printed as name/company/title/score/tier.

```
/network-intel search for "AI startup"
```

```bash
node scripts/analyze.mjs --mode search --query "cloud infrastructure"
```

`--query` is required for this mode.

## 7. recommend

Surfaces the single highest-value next action.

**Calls:** `GET /api/actions/next`

**Returns:** Whatever the endpoint identifies as the next-best action -- a pending task, an outreach step, or an enrichment/import suggestion, along with the associated contact if any.

```
/network-intel what should I focus on next?
```

```bash
node scripts/analyze.mjs --mode recommend
```

## 8. company

Deep-dive into a specific company's contacts in your network.

**Calls:** `GET /api/contacts?company=<name>`

**Returns:** All matching contacts, printed as name/company/title/score/tier, with a total count.

```
/network-intel show me contacts at Acme Corp
```

```bash
node scripts/analyze.mjs --mode company --name "Acme Corp"
```

`--name` is required for this mode.

## Options Reference

| Option | Used By | Description |
|--------|---------|--------------|
| `--mode <mode>` | All | Analysis mode (required) |
| `--top <N>` | hubs, prospects, referrals | Number of results (default 10) |
| `--query "text"` | search | Free-text search query (required) |
| `--name "<company>"` | company | Company name to search (required) |

## Modes With No V2 Equivalent

The retired v1 analyzer (`agent/network-navigator/.v1-archive/`) supported four additional modes that were not carried forward into `analyze.mjs`:

| Mode | What It Did in v1 | Status in v2 |
|------|---------------------|----------------|
| `behavioral` | Ranked contacts by behavioral score and persona (super-connector, content-creator, etc.) | The behavioral dimension still feeds the composite score, but there is no CLI mode or endpoint that ranks/filters contacts by behavioral persona alone. |
| `visibility` | Content-strategy recommendations (who to engage, bridge connectors, silent influencers) | No v2 equivalent -- this was computed entirely from the local `graph.json` in v1 and was not ported to the app. |
| `employers` | Ranked companies by an "Employer Network Value" composite score | No v2 equivalent -- there is no company-ranking endpoint. |
| `similar` | k-NN similarity search from a specific contact's stored vector | No v2 equivalent script or endpoint exists for this specific case; `search` (hybrid keyword+vector) is the closest available capability, but it takes a free-text query rather than a target contact. |

If you need any of these, they would have to be rebuilt against the app's API and data model -- the v1 implementations operated on local JSON files that no longer exist.
