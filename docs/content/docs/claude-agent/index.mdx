# Claude Agent

The Claude Agent is a portable [Claude Code](https://docs.anthropic.com/en/docs/claude-code) skill that provides LinkedIn network intelligence through two slash commands. It is **API-first**: every operation goes through the NetworkNav REST API at `localhost:3750`. There is no Playwright, no local JSON data store, and no browser automation inside the agent -- LinkedIn capture happens through the browser extension as you browse.

## Three Subsystems

NetworkNav is built from three cooperating subsystems, each with a distinct role:

```
+------------------+        +------------------+        +------------------+
|   Web App        |        |   Claude Agent   |        | Browser Extension|
|   (app/)         |<------>|   (agent/)       |<------>|   (browser/)     |
|                  |  REST  |                  |  REST  |                  |
| Next.js dashboard|  API   | Claude Code skill|  API   | Chrome MV3       |
| PostgreSQL + RVF |        | 4 REST scripts   |        | Page capture     |
| Scoring engine   |        | No local state   |        | Task display     |
| Outreach mgmt    |        | No browser auto  |        | Auto-paginate    |
| REST API         |        |                  |        | search results   |
+------------------+        +------------------+        +------------------+
```

| Subsystem | Role | Data Flow |
|-----------|------|-----------|
| **Web App** | Web UI and persistent storage. Dashboard, contacts table, scoring engine, graph analysis, enrichment management, outreach pipeline, REST API. | Owns all data in PostgreSQL. Serves the dashboard UI. Receives captured data from the extension. |
| **Claude Agent** | REST client. Configuration wizard, pipeline orchestration, and read-only analysis, all via HTTP calls to the app. | Holds no local state. Every command is a `GET`/`POST`/`PUT` against the app's API. |
| **Browser Extension** | Active data capture. Extracts profile data from LinkedIn pages you visit, displays tasks, can auto-paginate search results. | Sends captured page data to the app API. Displays tasks and context surfaced by the app. |

The agent has no independent existence apart from the app -- it cannot run offline, and there is nothing for it to do if the app isn't running. All scoring, storage, and analysis logic lives server-side.

## Two Slash Commands

| Command | Purpose |
|---------|---------|
| `/linkedin-prospector` | Configure ICP profiles, niches, and offerings; validate and list current configuration |
| `/network-intel` | Score contacts, run analysis, search, and surface recommended next actions |

## Scoring Engine

Scoring runs entirely in the app, backed by PostgreSQL:

| Phase | What It Measures | Key Outputs |
|-------|--------------------|-------------|
| **Phase 1: Composite Score** | Nine weighted dimensions -- ICP fit, network hub, relationship strength, signal boost, skills relevance, network proximity, behavioral, content relevance, graph centrality | Composite score, Tier (gold/silver/bronze/watch), Persona |
| **Phase 2: Referral Score** | Referral role, client overlap, network reach, amplification power, relationship warmth, buyer inversion | Referral likelihood, Referral tier, Referral persona (e.g. white-label-partner, warm-introducer, co-seller, amplifier) |

See [Scoring Pipeline](/docs/claude-agent/scoring-pipeline) for the full dimension breakdown and weight defaults.

## Semantic and Hybrid Search

The app integrates the [ruvector](https://github.com/ruvnet/ruvector) PostgreSQL extension for vector search. Contact profile text is embedded and indexed with HNSW, and `GET /api/contacts/hybrid-search` combines keyword (trigram) and vector similarity ranking, with an automatic fallback to keyword-only search if the vector extension is unavailable.

See [Semantic Search](/docs/claude-agent/semantic-search) for details.
