# Scoring Pipeline

Scoring runs entirely server-side in the app (`app/src/lib/scoring/`), backed by PostgreSQL. The agent never scores anything itself -- it triggers scoring runs and reads results through the REST API.

## Two-Phase Architecture

```
Phase 1: Composite Score   (9 weighted dimensions, computed together)
    |
    v
Phase 2: Referral Score    (6 weighted dimensions, computed after Phase 1)
```

Phase 2 reads the Phase 1 result (specifically the behavioral persona) as one of its inputs, so referral scoring always runs after composite scoring completes.

## Phase 1: Composite Score

Nine dimension scorers each produce a raw score (0-1) for a contact; the composite score is their weighted sum.

| Dimension | Default Weight | What It Measures |
|-----------|------------------|--------------------|
| `icp_fit` | 0.20 | Role match, industry match, signal match, company size fit against active ICP profiles |
| `relationship_strength` | 0.15 | Mutual connections, recency, proximity |
| `network_hub` | 0.10 | Connection count, cluster breadth, connector role |
| `signal_boost` | 0.10 | High-intent keywords in headline/about |
| `skills_relevance` | 0.10 | Overlap between contact skills and ICP signals |
| `behavioral` | 0.10 | Activity level, engagement signals, connection power |
| `content_relevance` | 0.10 | Content topics, posting frequency, engagement |
| `graph_centrality` | 0.10 | PageRank, betweenness, degree centrality |
| `network_proximity` | 0.05 | Graph distance and shared network paths |

Weights are configurable per-profile via `PUT /api/scoring/weights` and must sum to 1.0. Dimensions with no data available for a given contact have their weight redistributed proportionally across the remaining dimensions rather than being scored as zero.

### Tier Assignment

| Tier | Threshold | Meaning |
|------|-----------|---------|
| **gold** | composite score >= 0.55 | Top prospects -- pursue immediately |
| **silver** | >= 0.40 | Good prospects -- nurture relationship |
| **bronze** | >= 0.28 | Some potential -- monitor and engage |
| **watch** | < 0.28 | Low priority -- passive awareness |

### Persona Classification

Computed from the raw (unweighted) dimension scores, checked in order -- first match wins:

| Persona | Condition |
|---------|-----------|
| `buyer` | `icp_fit` > 0.6 AND `relationship_strength` > 0.4 |
| `warm-lead` | `icp_fit` > 0.4 AND `relationship_strength` > 0.3 |
| `active-influencer` | `behavioral` > 0.6 AND `content_relevance` > 0.4 |
| `hub` | `network_hub` > 0.6 |
| `advisor` | `relationship_strength` > 0.6 AND `icp_fit` > 0.2 |
| `passive-contact` | Default for 1st/2nd degree connections |
| `unknown` | Default otherwise |

### Behavioral Persona Classification

A second, independent classification, also checked in order:

| Persona | Condition |
|---------|-----------|
| `data-insufficient` | The behavioral scorer had fewer than 2 available signal components |
| `super-connector` | `network_hub` > 0.7 AND 500+ connections |
| `content-creator` | `content_relevance` > 0.5 AND `behavioral` > 0.5 |
| `silent-influencer` | `graph_centrality` > 0.5 AND `behavioral` < 0.3 |
| `rising-connector` | Under 500 connections AND connected within the last 180 days |
| `engaged-professional` | `behavioral` > 0.3 |
| Default | Passive/no strong signal |

## Phase 2: Referral Score

Six weighted components evaluate a contact's ability to send you business:

| Component | Weight | What It Measures |
|-----------|--------|--------------------|
| `referralRole` | 0.25 | Role-based referral potential (agency, partner, consultant, advisor) |
| `clientOverlap` | 0.20 | Whether they serve the same industries you target |
| `networkReach` | 0.20 | Connection count, cluster breadth, edge density |
| `amplificationPower` | 0.15 | Super-connector traits, content-creation signals |
| `relationshipWarmth` | 0.10 | Mutual connections, existing relationship strength, recency |
| `buyerInversion` | 0.10 | Inverse ICP fit + ecosystem keywords (partner, not buyer) |

Like Phase 1, null components have their weight redistributed proportionally.

### Referral Tiers

| Tier | Threshold | Meaning |
|------|-----------|---------|
| `gold-referral` | referral score >= 0.65 | Strong referral partner |
| `silver-referral` | >= 0.45 | Good potential |
| `bronze-referral` | >= 0.30 | Some potential |
| (none) | < 0.30 | Not currently a referral candidate |

### Referral Persona Classification

Checked in order -- first match wins:

| Persona | Condition |
|---------|-----------|
| `white-label-partner` | Agency/consultancy role in title or headline AND `referralRole` >= 0.7 AND `clientOverlap` >= 0.4 |
| `warm-introducer` | `relationshipWarmth` >= 0.5 AND `networkReach` >= 0.5 |
| `co-seller` | Consultant/advisor/freelance/fractional role AND `clientOverlap` >= 0.5 |
| `amplifier` | `amplificationPower` >= 0.5 OR existing behavioral persona is `super-connector`/`content-creator` |
| `passive-referral` | Default |

## Triggering and Reading Scoring Runs

The agent has no scoring logic of its own -- it calls these endpoints:

| Endpoint | Method | What It Does |
|----------|--------|----------------|
| `/api/scoring/rescore-all` | POST | Re-scores all contacts (composite + referral). Returns `{ runId, status: "running" }`. |
| `/api/scoring/run` | POST | Score a single contact or batch |
| `/api/scoring/status` | GET | Poll a run's status by `runId` (or the latest run if omitted) |
| `/api/scoring/weights` | GET/PUT | View or update per-profile scoring weights |
| `/api/scoring/preview` | POST | Preview score changes before applying |

```
/network-intel rescore everything
```

```bash
node agent/network-navigator/skills/linkedin-prospector/scripts/pipeline.mjs --rescore-all
```

`pipeline.mjs --rescore-all` kicks off the run and then polls `/api/scoring/status` every 2 seconds (up to 60 attempts, i.e. 2 minutes) until the run reports `complete`, `idle`, or `done`.

### When to Rescore

New contacts captured via the browser extension are scored automatically. A manual rescore is needed when:
- ICP profiles or criteria change
- Scoring weights change
- Enrichment data arrives in bulk (e.g. after an import)
