# Semantic Search

The app integrates [ruvector](https://github.com/ruvnet/ruvector) as a PostgreSQL extension to provide vector search across your contact network. Embedding, storage, indexing, and querying all happen server-side in the database -- the agent has no embedding code of its own and does not need any extra dependency installed.

<Callout type="info">
This is a change from the retired v1 architecture, where the agent installed `ruvector` as an npm package, ran a local ONNX embedder, and stored vectors in a `.rvf` file on disk. In v2, ruvector runs inside PostgreSQL, and the agent just calls `GET /api/contacts/hybrid-search`.
</Callout>

## How It Works

Each contact's profile text (headline, title + current company, and the first 500 characters of their about section) is embedded using the **all-MiniLM-L6-v2** model (loaded server-side via `@huggingface/transformers`) and stored as a 384-dimensional vector in the `profile_embeddings` table. Separate `content_embeddings` and `company_embeddings` tables hold vectors for other content types using the same model.

When you search, `GET /api/contacts/hybrid-search?q=<query>` runs a single SQL query that:

1. Finds keyword matches using PostgreSQL trigram similarity (`pg_trgm`) against name, headline, title, and company
2. Finds vector matches by embedding the query with `ruvector_embed('all-MiniLM-L6-v2', $query)` and ranking the nearest 50 profile embeddings by cosine distance
3. Fuses the two into a single score: **`fusion_score = 0.4 * keyword_score + 0.6 * vector_score`**
4. Returns the top results ordered by fusion score

If the `ruvector_embed` function or the vector extension is unavailable, the endpoint automatically falls back to keyword-only search (trigram similarity alone).

## What Semantic Search Finds That Keywords Miss

| Keyword Search For... | Also Finds (via Semantic Similarity)... |
|---|---|
| "AI consultant" | "machine learning advisor", "data science practice lead" |
| "ecommerce founder" | "DTC brand builder", "Shopify agency owner" |
| "VP Engineering" | "Head of Platform", "Director of Software Development" |
| "growth marketing" | "demand generation", "customer acquisition", "performance marketing" |

## Using It

### From the agent

```
/network-intel search for "cloud infrastructure"
/network-intel who talks about AI transformation?
```

```bash
node agent/network-navigator/skills/linkedin-prospector/scripts/analyze.mjs --mode search --query "AI transformation leaders" --top 20
```

`analyze.mjs --mode search` calls `GET /api/contacts/hybrid-search?q=<query>` and prints the top 20 results.

### Directly via the API

```
GET /api/contacts/hybrid-search?q=cloud+infrastructure
```

## Embedding Details

| Property | Value |
|----------|-------|
| Model | `Xenova/all-MiniLM-L6-v2` (via `@huggingface/transformers`, dtype `fp32`) |
| Dimensions | 384 |
| Distance metric | Cosine (`ruvector_cosine_ops`) |
| Index | HNSW, `m = 16`, `ef_construction = 200` |
| Tables | `profile_embeddings`, `content_embeddings`, `company_embeddings` |
| Source text (profiles) | `headline` \| `title at current_company` \| first 500 chars of `about` |

## Keeping Embeddings Current

Embeddings are generated when contacts are imported or captured, and can be backfilled for any contacts missing one via the app's reindex path (`POST /api/admin/reindex`). There is no agent-side vectorize step to run -- embedding generation is not exposed through `pipeline.mjs` or `analyze.mjs`.

## Troubleshooting

| Issue | Fix |
|-------|-----|
| Search returns keyword-only results, no semantic matches | The `ruvector_embed` function or the ruvector-postgres extension isn't available; check `docker compose logs db` |
| No results at all | The contact may not have an embedding yet; trigger a reindex via `POST /api/admin/reindex` |
| Slow first query | The embedding model is loaded lazily on first use in the app process; subsequent queries are fast |

## What's No Longer Here

The retired v1 architecture had a dedicated `similar` analysis mode -- k-NN search from a specific contact's stored vector, distinct from free-text semantic search. That mode has no v2 equivalent; `hybrid-search` only accepts a free-text query, not a target contact ID. See [Analysis Modes](/docs/claude-agent/analysis-modes#modes-with-no-v2-equivalent) for details.
