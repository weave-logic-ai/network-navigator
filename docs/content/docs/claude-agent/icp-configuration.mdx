# ICP Configuration

The ICP (Ideal Customer Profile) configuration is the core of how contacts are scored, tiered, and searched. In v2, configuration lives entirely in PostgreSQL and is managed through REST APIs -- there are no local JSON config files.

| Entity | API | Purpose |
|--------|-----|---------|
| ICP Profiles | `POST /api/icps` | Ideal buyer criteria (roles, industries, signals, company size) |
| Niches | `POST /api/niches` | Named groups of search keywords |
| Offerings | `POST /api/offerings` | Your services/products, one per business line |

## Setup Methods

### Method 1: Conversational via Claude (recommended)

```
/linkedin-prospector set up my ICP config
```

Claude conducts a structured conversation asking about your business, then creates the configuration via API calls. This is the recommended approach.

### Method 2: Non-interactive CLI

Pass the full configuration as JSON for automation:

```bash
node agent/network-navigator/skills/linkedin-prospector/scripts/configure.mjs generate --json '{...full config JSON...}'
```

### Method 3: Direct API calls

Use `curl` or any HTTP client to call `POST /api/icps`, `/api/niches`, `/api/offerings` directly. See the [API Reference](/docs/api-reference) for full request/response shapes.

<Callout type="warn">
There is no interactive terminal wizard (`configure.mjs wizard`) in v2 -- the script only accepts `validate`, `list`, and `generate --json`. The conversational flow lives in the `/linkedin-prospector` agent, not in the script.
</Callout>

## The Agent's Configuration Flow

When you ask Claude to configure your ICP, it follows this structured process:

<Steps>

### Ask about services

> "What services do you offer?"

Each service becomes one offering and one or more ICP profiles. Example: "I do AI consulting and fractional CTO work" produces two offerings and two ICP profiles.

### Ask about target buyers (per service)

> "For [service], who are your ideal buyers? List the job titles starting with highest priority."

Maps to the ICP's `criteria.roles` array. Keywords use partial matching: "VP" matches "VP Engineering", "VP Product", etc. "Head of" matches "Head of Engineering", "Head of AI", etc.

### Ask about target industries

> "What industries are your ideal customers in?"

Maps to `criteria.industries`. Include synonyms -- LinkedIn profiles use inconsistent terminology ("ecommerce" and "e-commerce", "saas" and "software").

### Ask about buying signals

> "What keywords in someone's profile would signal they might need [service]?"

Maps to `criteria.signals`. Think about problems ("scaling"), initiatives ("digital transformation"), or technologies ("AI").

### Ask about company size (optional)

> "What's the ideal company size range?"

Maps to `criteria.companySizeRanges`. Default: `["11-50", "51-200", "201-500"]`.

### Ask about search niches

> "What keywords should I search for on LinkedIn? Group them into niches."

Each niche becomes a `POST /api/niches` call with a name and a `keywords` array.

### Assemble and call the API

Claude either calls `POST /api/icps` / `/api/niches` / `/api/offerings` directly, or bundles everything into one call:

```bash
node scripts/configure.mjs generate --json '<assembled JSON>'
```

### Validate and confirm

```bash
node scripts/configure.mjs validate
```

Claude reports back the number of ICP profiles, niches, and offerings created, and suggests the next step (capture contacts via the browser extension).

</Steps>

## ICP Profile Fields

**`POST /api/icps` request body:**

| Field | Type | Required | Description |
|-------|------|----------|--------------|
| `name` | string | Yes | Human-readable profile name |
| `description` | string | No | Who this profile targets |
| `criteria` | object | Yes | Matching criteria (below) |
| `is_active` | boolean | No | Whether this profile is active (default: true) |

**`criteria` object:**

| Field | Type | Description |
|-------|------|-------------|
| `roles` | string[] | Role keywords matched against contact titles |
| `industries` | string[] | Industry keywords matched against profile text |
| `signals` | string[] | Buying-intent keywords matched against headline/about |
| `companySizeRanges` | string[] | Employee count ranges, e.g. `"11-50"`, `"201-500"` |
| `locations` | string[] | Geographic keywords (optional) |
| `minConnections` | number | Minimum connection count (optional) |

## Scoring Weights

Composite scoring weights are managed via `GET`/`PUT /api/scoring/weights`, not a config file. The nine dimensions must sum to 1.0:

| Dimension | Default Weight | What It Measures |
|-----------|-----------------|--------------------|
| `icp_fit` | 0.20 | Match against your ICP criteria |
| `network_hub` | 0.10 | Connection count, cluster breadth, connector role |
| `relationship_strength` | 0.15 | Mutual connections, recency, proximity |
| `signal_boost` | 0.10 | High-intent keywords in headline/about |
| `skills_relevance` | 0.10 | Overlap between contact skills and ICP signals |
| `network_proximity` | 0.05 | Graph distance and shared network paths |
| `behavioral` | 0.10 | Activity level, engagement signals, connection power |
| `content_relevance` | 0.10 | Content topics, posting frequency, engagement |
| `graph_centrality` | 0.10 | PageRank, betweenness, degree centrality |

```bash
PUT /api/scoring/weights
{
  "name": "default",
  "weights": {
    "icp_fit": 0.20, "network_hub": 0.10, "relationship_strength": 0.15,
    "signal_boost": 0.10, "skills_relevance": 0.10, "network_proximity": 0.05,
    "behavioral": 0.10, "content_relevance": 0.10, "graph_centrality": 0.10
  }
}
```

### Tier Thresholds

| Tier | Default Threshold | Meaning |
|------|--------------------|---------|
| Gold | >= 0.55 | High-priority prospects |
| Silver | >= 0.40 | Worth pursuing |
| Bronze | >= 0.28 | Keep on radar |
| Watch | < 0.28 | Not a current fit |

## Validation

Always validate after modifying configuration:

```bash
node scripts/configure.mjs validate
```

This calls `GET /api/icps`, `GET /api/niches`, and `GET /api/offerings`, then reports counts and warns if any of the three are empty.

## Example: Solo AI Consultant

```json
{
  "profiles": {
    "ai-consulting": {
      "name": "AI Consulting",
      "description": "Leaders exploring AI for their business",
      "criteria": {
        "roles": ["CEO", "CTO", "Founder", "Chief Digital", "VP", "Director", "Head of", "Manager", "Lead"],
        "industries": ["saas", "ecommerce", "fintech", "healthcare"],
        "signals": ["ai", "artificial intelligence", "automation", "digital transformation"],
        "companySizeRanges": ["11-50", "51-200", "201-500"]
      }
    }
  },
  "niches": {
    "ai": { "name": "AI", "keywords": ["AI", "artificial intelligence", "machine learning"] },
    "saas": { "name": "SaaS", "keywords": ["SaaS", "software platform", "cloud"] },
    "ecommerce": { "name": "Ecommerce", "keywords": ["ecommerce", "e-commerce", "DTC", "Shopify"] }
  },
  "offerings": [
    { "name": "AI Consulting", "description": "Strategic AI consulting for mid-market companies" }
  ]
}
```

## Example: Multi-Service Agency

Create multiple ICP profiles -- one per service:

```json
{
  "profiles": {
    "web-development": {
      "name": "Web Development",
      "criteria": {
        "roles": ["CTO", "VP Engineering", "Director Engineering", "Head of Product"],
        "industries": ["saas", "ecommerce", "fintech"],
        "signals": ["redesign", "new website", "web platform", "migration"]
      }
    },
    "seo-services": {
      "name": "SEO Services",
      "criteria": {
        "roles": ["CMO", "VP Marketing", "Director Marketing", "Head of Growth"],
        "industries": ["ecommerce", "saas", "media", "publishing"],
        "signals": ["organic traffic", "SEO", "search ranking", "content strategy"]
      }
    }
  }
}
```

The scoring engine evaluates each contact against all active ICP profiles and uses the best-fit score.

## Tuning Tips

After your first analysis, review the results and tell Claude what to adjust:

| Observation | What to Tell Claude |
|-------------|------------------------|
| Too many gold contacts | "Raise the gold threshold" or "increase icp_fit weight" |
| Wrong people flagged as referral partners | "Narrow the referral role criteria" |
| Network hubs not getting credit | "Increase the network_hub weight" |

Then rescore: `/network-intel rescore everything`
