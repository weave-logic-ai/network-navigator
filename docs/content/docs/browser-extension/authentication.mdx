# Authentication

The extension authenticates with the NetworkNav app using a token-based system. Before the extension can submit captures or fetch tasks, it must be registered with a valid token.

## How Token Auth Works

The authentication flow uses a full bearer token:

1. The local operator unlocks the app and generates a token on the Extension page
2. The token has the format `ext_` followed by 32 random bytes encoded as base64url
3. A SHA-256 hash of the token is stored in the `extension_tokens` database table
4. The user enters the full token in the extension popup or sidepanel
5. The extension sends the full token to `POST /api/extension/register`
6. The server hashes it, looks up the matching row, and returns an `extensionId` and default settings
7. The extension stores the token in `chrome.storage.local` and includes it in all subsequent API requests via the `X-Extension-Token` header

<Callout type="warn">
The full token is stored in the extension's local storage and sent with authenticated requests. Only its hash is stored on the server. The 12-character display prefix shown in the app cannot authenticate. Revoke or replace tokens on the operator's Extension page.
</Callout>

## Generating a Token

<Steps>

Open the local app's `/operator/unlock` page and enter the operator secret from your ignored local environment. On the Extension page, select **Generate New Token**. Copy the full token before closing the dialog; it is displayed only once. Tokens expire one year after creation. Generate a replacement before expiry and revoke the previous token after reconnecting.

</Steps>

## Registering the Extension

<Steps>

### Open the extension popup

Click the extension icon in the Chrome toolbar. Since this is the first launch, you will see the "Connect to App" registration form.

### Enter the full token

Paste the complete value beginning with `ext_` into the text input field. A listed display prefix will be rejected.

### Click Connect

The extension sends the token to `POST /api/extension/register` on the configured app URL (default `http://localhost:3750`).

### Verify registration

If successful, the registration form disappears and is replaced by the main dashboard showing:

- **Captures Today**: 0
- **Queued**: 0
- **Tasks**: 0
- Connection status indicator showing "Connected" (green)

If registration fails, an error message appears: "Registration failed. Check your token and try again."

</Steps>

## Token Storage

After registration, the extension stores two values in `chrome.storage.local`:

| Key | Value | Purpose |
|-----|-------|---------|
| `extensionToken` | The full token string | Sent as `X-Extension-Token` on authenticated HTTP requests |
| `extensionId` | The server-assigned extension ID | Identifies this extension instance for rate limiting and logging |

The server-side `withExtensionAuth()` middleware validates every incoming request by:

1. Reading the `X-Extension-Token` header
2. Computing its SHA-256 hash
3. Looking up the hash in `extension_tokens`
4. Checking revocation and one-year expiry
5. Validating the exact configured Chrome extension origin and loopback Host

## Token Security

- The server never stores the raw token. Only the SHA-256 hash is persisted in the database.
- Token validation includes an explicit `EXTENSION_ALLOWED_ORIGINS` allowlist; an arbitrary extension origin is rejected.
- The server enforces per-extension rate limiting. Exceeding the rate limit returns HTTP 429 with a `Retry-After` header.
- Failed authentication returns HTTP 401 with a structured JSON error body.

## Re-authentication

You need to re-register the extension when:

- **The token is revoked or expires.** The extension will receive 401 errors on authenticated API calls.
- **The token is deleted.** The token row is removed from the database.
- **The extension storage is cleared.** If `chrome.storage.local` is wiped (e.g., reinstalling the extension), the stored token is lost.

Mint a new full token on the operator's Extension page, then enter it in the popup or sidepanel reconnect form. The popup also checks a saved token when opened and offers reconnection if it was revoked or expired.

## Verifying Token Status

The operator's Extension page lists active tokens by masked prefix and lets the operator revoke them. If a token is no longer accepted, mint a replacement and reconnect with its full value.
